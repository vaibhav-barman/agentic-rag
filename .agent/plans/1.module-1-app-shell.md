# 1. Module 1: App Shell + Observability

**Complexity:** ⚠️ **Medium** - four phases executed in order, each with its own validations. Run one phase per pass and stop between phases to validate.

| Phase | Complexity |
|---|---|
| A. Project setup + auth | ⚠️ Medium |
| B. Chat with the Responses API | ⚠️ Medium |
| C. Minimal document upload | ⚠️ Medium |
| D. LangSmith tracing | ✅ Simple |

## Goal
Auth, a threaded chat UI streaming answers from the OpenAI Responses API (managed memory and `file_search`), a minimal upload page feeding an OpenAI vector store, and LangSmith tracing. Module 2 replaces the Responses API and vector store, so all OpenAI-specific code lives in `backend/app/services/openai_responses.py` for easy removal.

## Decisions
- Supabase: hosted project (no Docker).
- Auth: email + password.
- One OpenAI vector store per user, id stored in Supabase.
- Messages stored in Supabase for display; model memory via `previous_response_id`.
- Frontend reads SSE with `fetch` plus a stream reader so the auth header is sent.
- Backend verifies the Supabase JWT on every request.

## Prerequisites (user provides, in `.env` files only; commit `.env.example`)
- Supabase: URL, anon key, service-role key, JWT secret (or JWKS URL).
- OpenAI: `OPENAI_API_KEY`, `OPENAI_MODEL`.
- LangSmith: `LANGSMITH_API_KEY`, `LANGSMITH_PROJECT`, `LANGSMITH_TRACING=true`.

## Phase A: Project Setup + Auth

### A.1 Backend scaffold
- `backend/`: `python3 -m venv venv`, install `fastapi`, `uvicorn[standard]`, `pydantic-settings`, `supabase`, `pyjwt`, `pytest`, `httpx`; freeze to `requirements.txt`.
- `app/main.py` (CORS for the Vite dev origin, `GET /health`), `app/config.py` (pydantic-settings), `.env.example`.
- **Validation:** `pytest tests/test_health.py` - `GET /health` returns 200 `{"status":"ok"}`.

### A.2 Database migration
- `supabase/migrations/0001_init.sql`: `threads` (id, user_id, title, last_response_id, created_at), `messages` (id, thread_id, user_id, role, content, created_at), `user_vector_stores` (user_id PK, vector_store_id), `documents` (id, user_id, filename, openai_file_id, status, created_at).
- RLS on every table; policies allow select/insert/update/delete only where `auth.uid() = user_id`.
- **Validation:** with two test users, user B selecting user A's rows gets zero rows, and inserting with a foreign `user_id` is rejected.

### A.3 Backend auth dependency
- `app/auth.py`: `get_current_user` validates the `Authorization: Bearer` JWT and returns the user id. `GET /me` returns id and email.
- **Validation:** `pytest` - `/me` returns 401 with no or a bad token, 200 with a valid one.

### A.4 Frontend scaffold
- `frontend/`: Vite React TS, Tailwind, shadcn/ui, `react-router-dom`, `@supabase/supabase-js`.
- `src/lib/supabase.ts` (from `VITE_SUPABASE_URL` / `VITE_SUPABASE_ANON_KEY`), `src/lib/api.ts` (fetch wrapper attaching the access token).
- **Validation:** `npm run build` and `npm run lint` pass; the dev server renders.

### A.5 Auth UI + routing
- `Login` page (sign up, log in, errors), session listener, protected routes, nav with **Chat** (`/`, default) and **Ingestion** (`/ingestion`), log out.
- **Validation (browser):** sign up, log in, land on Chat, reload and stay signed in, log out and get redirected; `/` while signed out redirects to login; `/me` from the UI returns the signed-in email.

## Phase B: Chat with the Responses API

### B.1 Responses service
- `app/services/openai_responses.py` is the only module importing the OpenAI SDK. An async generator calls `client.responses.create(model, input, previous_response_id, stream=True)` and yields text deltas plus the final `response.id`.
- If the user has a `user_vector_stores` row, add `tools=[{"type":"file_search","vector_store_ids":[...]}]`.
- Pydantic request/response models in `app/schemas.py`.
- **Validation:** unit test with OpenAI mocked: deltas in order, final id captured, `file_search` included only when a store exists.

### B.2 Thread endpoints
- `POST /threads`, `GET /threads`, `GET /threads/{id}/messages`, scoped to the current user.
- **Validation:** `pytest` - create, list, fetch messages; another user's thread returns 404.

### B.3 Chat endpoint (SSE)
- `POST /threads/{id}/chat` returns `text/event-stream`: `delta` events, then `done`.
- On completion, persist user and assistant messages, update `threads.last_response_id`, and set the title from the first message if empty.
- **Validation:** `pytest` with OpenAI mocked: SSE body has deltas and `done`, both messages stored, `last_response_id` updated. Live: a second message referring to the first shows memory carried over.

### B.4 Chat UI
- Thread sidebar (list, new, select), message list, input box, streaming render.
- **Validation (browser):** text streams in; reload keeps history; switching threads shows each thread's messages; follow-ups keep context.

## Phase C: Minimal Document Upload

### C.1 Vector store service
- In `openai_responses.py` (or an equally deletable sibling): `get_or_create_vector_store(user_id)`, `upload_file(...)`, `delete_file(...)`; store id saved in `user_vector_stores`.
- **Validation:** unit test with OpenAI mocked: first call creates and saves a store, second call reuses it.

### C.2 Document endpoints
- `POST /documents` (multipart): create store if needed, `vector_stores.files.upload_and_poll`, insert a `documents` row with status. `GET /documents`, `DELETE /documents/{id}` (removes from vector store and deletes the row).
- Small file-type allow-list and size cap with clear errors.
- **Validation:** `pytest` with OpenAI mocked: upload, list, delete work; bad type returns 4xx; another user can't list or delete.

### C.3 Ingestion UI
- Drag-and-drop zone, upload status, document list with delete.
- **Validation (browser):** drop a small text file, see it processed, delete it, see it gone.

### C.4 End-to-end retrieval
- **Validation (live):** upload a file with a fact the model can't know, ask about it in Chat, confirm the answer uses it (and cites the file if annotations are returned). Delete the file, ask again, confirm the fact is gone.

## Phase D: LangSmith Tracing

### D.1 Wrap the OpenAI client
- Install `langsmith`; wrap the client with `langsmith.wrappers.wrap_openai`. No LangChain or LangGraph.
- **Validation:** tests still pass with tracing off; with tracing on, one chat call produces a run in the LangSmith project.

### D.2 Metadata
- `@traceable` (or `langsmith_extra`) tags each run with `user_id`, `thread_id`, and whether `file_search` was enabled.
- **Validation:** the trace shows inputs, streamed output, model, token usage, and the metadata.

### D.3 Setup docs
- Add `LANGSMITH_*` to `backend/.env.example`.
- **Validation:** a fresh clone with a filled-in `.env` produces traces with no extra steps.

2. Sign up and log in, upload a document, start a thread, ask about the document, and get a streamed, grounded answer. Reload: history persists.
3. Follow-up keeps context.
4. The LangSmith trace is present; the RLS cross-user test passes.
5. Update `PROGRESS.md` after each phase and commit.
